# Safety API (SAF-003)

Authenticated member commands, exact CORS, no-store DTOs and trusted transaction actor apply. IDs below are scoped assignment/case IDs, never caller-supplied target account IDs. No public tick, clock, capability grant or block removal route.

- GET /member/safety: {state:ACTIVE|WARNING|RESTRICTED|BANNED,reports:[{id,category,status,createdAt}],contexts:[{assignmentId,startsAt,regionLabel,peers:[{peerId,label,separated}]}]}. Own newest20 historical assignments and reports. Chat participant numbers identify peers; canceled/inactive assignments remain valid reporting evidence. Only own reports, no raw details/operator reasons/identities. separated reflects only the caller's own prior REPORT/BLOCK receipts, never the peer's action.
- POST /member/safety/submit: {assignmentId,peerId,requestKey,kind:BLOCK} or {assignmentId,peerId,requestKey,kind:REPORT,category:HARASSMENT|UNWANTED_CONTACT|OTHER,details:string10..2000}. Same-table owned nonself assignment + existing chat number. Exact shapes; same key/body hash replays current DTO, changed409. New reports max20 per rolling24hours, replay exempt. Both register a persistent symmetric pair exclusion; reports also create PENDING operator case. No automatic account sanction. Restriction state does not block reporting.
- GET /member/operations/safety: operator-only {canReview,cases:[{caseType:REPORT|ATTENDANCE|CANCELLATION,caseId,kind,status,at}]}, latest100. No private reporter/target IDs, names, contact, text or preferences. Confirmed current NO_SHOW and CANCELED_LATE become review cases; unchecked candidates do not.
- POST /member/operations/safety/detail: {caseType,caseId}, requires operator + private safety_reviewers capability. {caseType,caseId,state,revision,details:string|null,status,actions:[{action,reason,state,at}] (latest50)}. Raw report is explicitly limited to this endpoint/capability. Corrected acted-on attendance remains a CORRECTED history case for explicit restoration/completion; new sanctions require current evidence.
- POST /member/operations/safety/review: {caseType,caseId,requestKey,revision:int0..999999999,action:REVIEWED|DISMISS|WARN|RESTRICT|BAN|RESTORE,reason:string5..500}. Capability required on every request/replay; revision is target account safety revision, shared across all cases about that account. Same key/body hash replay, changed409; stale409. No operator account restriction/ban/restore. WARN never lifts a restriction; BAN cannot downgrade via RESTRICT. RESTORE is explicit; no timed expiry. DISMISS/review/restore never clears pair exclusion. Actions/audit and repair are atomic.

401 authentication;403 ownership/capability or PARTICIPATION_RESTRICTED for new participation;422 shape/query/clock;409 IDEMPOTENCY_CONFLICT/SAFETY_CONFLICT;429 SAFETY_RATE_LIMIT (Retry-After86400). Request body bounded16KiB.

Future unsafe confirmations are invalidated and requeued within selected dates/regions under the global matching fence; current/past safety-conflicted chat access is denied immediately and historical attendance stays intact. RESTRICTED/BANNED cannot create applications, pay, transfer or match; ordinary account access, reports and existing resolution/refund remain available. Future paid holds use safety_hold, offer store/original-transaction mock refund without auto charge/forfeiture/refund/extension. Existing membership refund limits stay intact. Restore requeues only submitted/paid/unspent holds with future selected slots and current financial eligibility; it never revives old tables or refunded/canceled applications. Existing legacy restricted flag remains separate.

Private capabilities must be provisioned/revoked via trusted backend configuration, not browser/API. Local tests use synthetic users and remove grants afterward. Production provisioning/deployment, block release, retention/deletion workflows and general operating metrics remain separate.

SAF-003 corrected cases: a confirmed attendance/cancellation case with prior safety actions remains visible as CORRECTED after source correction, so an authorized reviewer can RESTORE or mark REVIEWED. New sanctions against corrected evidence return409. Unacted candidates still have no case authority. Safety state/revision live in the separate safety_accounts ledger; existing member_accounts authentication locks/restricted flag stay unchanged.
