- 이번 소스의 로컬 프론트 lint/typecheck/테스트5개/build·Edge 타입/테스트33개·SQL24개·정책/매칭/신고/환불 경합이 통과했다. 모바일 전체 실행22/23 뒤 추천 선택자 수정·신규UI결제/최종 참가이력 분리 회귀를 통과해24종을 분리 확인했다. 마지막 관련6개는4.3분에 모두 통과했다. 단일 최종24개 전체 실행과 구분한다. 이전 배포의 [전체 CI 성공](https://github.com/ljh8450/serendipity-table/actions/runs/39122716284)을 이번 소스의 새 CI 성공으로 계산하지 않는다.
- 로컬 연속 행사 통합 검사: 실제 Cron으로 매칭→식당/방→D1/START→8명 체크인→피드백 요청/평가·비공개 선호→다음8명 매칭의11단계가 모두 통과했다. 명시 이동/보관/모의 환불·원결제 보존과 다음 회차 AVOID 분리·정상 흐름 운영자 개입0을 확인했다. 최초 fixture 시각 오류 수정 후 전체 재실행과 정리까지 성공했다.

운영 모집·동의 전문을 임의 발행하거나 실제 참가자를 탈퇴시키지 않았다. 모의 결제·환불은 PRD가 허용한 범위이며 실제 PG 성공을 뜻하지 않는다. 통합 검사에서 식당·프로필·결제는 명시적인 로컬 가상 fixture이며 실제 식당 예약 증거를 대신하지 않는다.

## 확인된 불일치와 미완료

2026-10-18 사용자 요청으로 아래 구현을 보완했다. 최신 배포·실제 검증 상태는 위 결과를 따른다.

- **PRD §7.0·§17 운영 규칙 설정:** SQL048/API/웹 폼으로 전역 최소 점수와 연령·성비·MBTI·관심사·대화 성향 가중치를 발행한다. 각0~100·합100 검증, 기대 버전 충돌 거부, 감사와 불변 정책 버전 보존. 확정 결과를 소급 변경하지 않으며 다음 실행부터 적용한다. 필수 제약은 변경할 수 없다.
- **PRD §7.2 결과 상세:** SQL049 참가자/운영 테이블 요약에 최고·최저 연나이/차이, 성별·MBTI 구성, 공통 관심사, 최소 기준/인원/연령/선택/관계 조건 평가, 이전 만남, 재배치·배치 사유·확정/실패 시각을 추가했다. 참가자는 본인 희망 성향 충족도와 익명 구성원의 일정·지역 충족을 확인한다. 운영자에게 타인의 비공개 선호 원문·개인별 점수를 제공하지 않는다. 생일을 수집하지 않으므로 만 나이로 표시하지 않는다.
- **PRD §11 자동 메시지 관리:** SQL051에서 확정 안내·전날·시작·큐레이션·대안 문구를 운영자가 버전 발행한다. 문구는 일반 텍스트 최대500자이며, 일정/식당/환불 기준은 서버가 생성한다. 발송 문구/버전은 스냅샷으로 보존하고 기존 발송을 재작성하지 않는다. 모바일에서 발견한 피드백 제목 퇴행은 기존 알림 DTO 보존 래퍼로 수정했다.
- **RET-02 날짜 선호:** SQL050에서 마지막 유효 참석 신청의 명시 선택 일정과 같은 KST 요일·시간대를 먼저 추천하고, 본인 재방문 의사·미래 시작순을 적용한다. 이전 지역 필터·마감/중복/겹침/제한 차단을 유지한다. 추천은 자동 이동/신청/결제가 아니다.
- **PRD §11 운영 조회/대시보드:** SQL052~053 회원/신청 상세의 최소 프로필·참석 이력·현재 참가 가능 여부, 신청의 모의 결제/환불·이용권/원결제 유지 정보, 금융 실패 예외와 연결 신청을 추가했다. 전체/회차별23개 업무 건수와 기존13개 분자/분모 지표를 제공한다. 안전 사건 원문은 별도 담당자 권한을 유지한다. 식당 배정 예외는 현재 확정 테이블별 중복 제외, 당일 취소는 KST 실제 취소일로 구분한다.
- **PRD §16 사용성 및 운영 증거:** 참가자 신청/내 식탁/참가 이력/알림/계정과 운영자 목적별 메뉴로 분리했다. 제출 후 결제 포커스·현재 매칭 우선·이력 분리·직접 링크/입력 보존·역할별 다음 행동을 검증했다. 사람이 최초 신청을5분 안에 마치는지, 모든 화면/상태의 읽기 편의, 실제 이메일/OAuth·OS 푸시·식당 예약·운영 행사 실증은 별도 확인해야 한다. 자동 테스트 성공을 이 증거로 바꾸지 않는다.

## 운영 자동화 수준

**정상 반복 처리 흐름은 자동화됐고, 운영 자료 설정·본인 선택·예외 판단은 사람의 역할이다. 실제 운영 자동화율을 백분율로 계산할 행사 수/운영 시간 자료는 없다.**

| 구분 | 현재 범위 |
|---|---|
| 서버 예약 자동화 | 활성 Cron10개. 매분 매칭·식당·방·앱알림·푸시 dispatch·예약콘텐츠·참석 종료·피드백·Auth 정리, 매시17분 개인정보 보존 정리. 새 보완은 Cron을 추가하지 않는다. |
| 자동 정상 처리 | 마감 매칭/재배치/확정, 재고 배정/방, 안내/리마인드/콘텐츠, 피드백 요청/미응답 리마인드, 관계·경험의 다음 매칭 반영, 재시도/중복 방지. |
| 참가자 행동 | 신청/결제 동의, 실패 후 이동·보관·환불 선택, 체크인·평가·사람 선호. 시스템이 대신 동의하지 않는다. |
| 운영 사전 설정 | 실제 동의/운영 정책·회차·검증된 식당 예약 재고, 매칭 기준·안내 문구, 담당자 권한. 실제 식당 예약 확보는 사람의 일이다. |
| 운영 예외 | 식당 부족/안전 확인, 재시도 소진·복구, 신고 판단·노쇼 확인/정정. 정상 미매칭의 본인 대안 선택과 구별한다. |
| 검증 경계 | 로컬 가상 연속 흐름의 운영자 개입0은 증거가 있으나 실제 행사 운영 실증/인력시간 절감률·OS 알림 표시를 뜻하지 않는다. |

## 직접 확인할 체크리스트

- [ ] 지정 운영 계정으로 로그인해 조회·CSV·예외 연결·13지표를 확인한다. 안전 원문 검토는 별도 승인된 담당 계정만 사용한다. 계정/비밀번호는 이 문서에 기록하지 않는다.
- [ ] 위 PRD 불일치 항목을 확인하고, 보완 결과가 요구 수준을 만족하는지 검수한다. 매칭 규칙/템플릿을 발행하고, 기존 결과·발송 내용은 유지되는지 확인한다.
- [ ] 실제 사용할 개인정보·운영 정책 전문과 보관 대상/기간을 확인한 뒤 발행한다. 테스트 동의 문구를 운영 전문으로 사용하지 않는다.
- [ ] 확인된 날짜/지역·정원·마감/매칭 시각으로 모집을 발행하고 실제 운영 식당의 리뷰·예약·가격/알레르기 적합성 증빙을 확인한다.
- [ ] 새 참가자로 프로필부터 동의·신청·모의 결제까지 직접 진행해5분 이내인지 측정한다. 휴대전화320/390px·확대·키보드/오류/재시도를 확인한다.
- [ ] Google/카카오를 사용할 경우 소유자 앱/provider/redirect를 설정한 뒤 실제 로그인·복귀·로그아웃을 확인한다. 이메일 확인 메일 수신·만료/거부·복귀도 확인한다.
- [ ] 지원 실제 기기에서 푸시를 허용하고 OS 알림을 눈으로 확인한다. 공급자 수락/worker 수신 성공만으로 OS 표시를 완료 처리하지 않는다.
- [ ] 동일 행사와 다음 회차를 연결해 PRD12개를 참가자 화면 중심으로 끊김 없이 시연한다. 실제 서비스 데이터의 탈퇴/삭제 검수는 가상 계정과 승인된 테스트 환경에서 수행한다.
- [ ] 참가자/운영자 URL·역할별 계정의 안전한 전달·모의 범위·알려진 제한·제출 및 서비스 유지 여부를 최종 확인한다.

## 재실행 방법

전체 로컬 기반 검사는 루트 PowerShell에서 `./scripts/verify.ps1`, 모바일 회귀는 실제 로컬 DB/Edge와 frontend build 후 e2e에서 `npm run test:e2e`로 수행한다. 연속 서버 검사는 로컬 Supabase/Cron 실행과 `node scripts/prepare-member-e2e.mjs`의 가상 동의/계정 준비 후, 루트에서 `node scripts/verify-prd-integration-local.mjs`로 실행한다. 전체 기반·모바일·연속 검사는 공유 fixture 경합을 피하도록 순차 실행한다. 검사는 가상 로컬 fixture를 만들고 정리하며 운영 DB를 대상으로 실행하지 않는다.

이번 보고서는 SQL053·최신 API/서비스 흐름 배포와 명시한 로컬/원격 검증 범위를 기준으로 한다. GitHub CI는 해당 main 커밋의 실행 결과를 확인하며, 이전 커밋의 성공을 새 소스의 성공으로 확대하지 않는다.
