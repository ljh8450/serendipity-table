## 확인된 불일치와 미완료

- **PRD §7.0·§17 운영 규칙 설정:** DB에는 버전별 최소 점수·가중치가 있고 모니터에서 기준을 조회한다. 운영자가 웹 UI/API로 기준을 변경하는 기능은 없다. DB 설정 존재만으로 운영 설정 화면 완료로 보지 않는다.
- **PRD §7.2 결과 상세:** 현재 DTO/화면은 인원·일정/지역·진행 이력·배치 이유·식당/방 중심이다. PRD에 열거된 최고/최저 연령·성비·MBTI 구성·조건별 평가·선호 충족·이전 만남 등 전체 요약을 참가자/운영자 화면에서 확인할 수 없다. 개인정보를 노출하지 않는 허용 요약 설계와 표시 보완이 필요하다.
- **PRD §11 자동 메시지 관리:** 시스템 GUIDE/D1/START 템플릿과 발송 이력/재시도는 있으나 운영자의 큐레이션·리마인드·대체 일정 템플릿 편집 기능은 없다. P1 CON-04와 겹치는 부분이 있어도 §11 필수 화면 전체 충족으로 표시하지 않았다.
- **RET-02 날짜 선호:** 추천은 이전 선택 지역·유효 참석/재방문 의사와 미래 회차 시작순을 사용한다. 과거 선택 날짜·요일/시간 선호를 반영하는 별도 로직은 확인되지 않았다.
- **PRD §11 운영 조회/대시보드:** 최소 허용 DTO·13지표·연결 조회는 구현됐으나 요구된 프로필/이전 참석·안전 이력과 모든 업무별 건수를 한 대시보드에서 제공하는 범위는 부분이다. 신청의 결제 상태 필터는 있지만 거래·환불 원장 상세와 금융 실패의 통합 예외 연결도 제한적이다. 비공개 선호/신고 원문을 일반 운영자에게 그대로 공개하는 방식으로 보완해서는 안 된다.
- **PRD §16 사용성:** 320/390px·운영200% 확대, 라벨·터치영역·포커스·넘침 자동 검사는 통과했다. 사람이 최초 신청을5분 안에 마치는지, 모든 화면/상태의 디자인·읽기 편의가 충분한지는 아직 직접 검증하지 않았다.

이 항목들은 테스트 프로그램의 실행 오류와 구분한 실제 구현 범위의 제한이다. 기능 테스트가 성공해도 위 미완료가 해소된 것으로 보지 않는다.

## 직접 확인할 체크리스트

- [ ] 지정 운영 계정으로 로그인해 조회·CSV·예외 연결·13지표를 확인한다. 안전 원문 검토는 별도 승인된 담당 계정만 사용한다. 계정/비밀번호는 이 문서에 기록하지 않는다.
- [ ] 위 PRD 불일치 항목을 확인하고, 보완 결과가 요구 수준을 만족하는지 검수한다. 현재 없는 운영 규칙/템플릿 편집을 사용 가능한 기능으로 가정하지 않는다.
- [ ] 실제 사용할 개인정보·운영 정책 전문과 보관 대상/기간을 확인한 뒤 발행한다. 테스트 동의 문구를 운영 전문으로 사용하지 않는다.
- [ ] 확인된 날짜/지역·정원·마감/매칭 시각으로 모집을 발행하고 실제 운영 식당의 리뷰·예약·가격/알레르기 적합성 증빙을 확인한다.
- [ ] 새 참가자로 프로필부터 동의·신청·모의 결제까지 직접 진행해5분 이내인지 측정한다. 휴대전화320/390px·확대·키보드/오류/재시도를 확인한다.
- [ ] Google/카카오를 사용할 경우 소유자 앱/provider/redirect를 설정한 뒤 실제 로그인·복귀·로그아웃을 확인한다. 이메일 확인 메일 수신·만료/거부·복귀도 확인한다.
- [ ] 지원 실제 기기에서 푸시를 허용하고 OS 알림을 눈으로 확인한다. 공급자 수락/worker 수신 성공만으로 OS 표시를 완료 처리하지 않는다.
- [ ] 동일 행사와 다음 회차를 연결해 PRD12개를 참가자 화면 중심으로 끊김 없이 시연한다. 실제 서비스 데이터의 탈퇴/삭제 검수는 가상 계정과 승인된 테스트 환경에서 수행한다.
- [ ] 참가자/운영자 URL·역할별 계정의 안전한 전달·모의 범위·알려진 제한·제출 및 서비스 유지 여부를 최종 확인한다.

## 재실행 방법

전체 로컬 기반 검사는 루트 PowerShell에서 `./scripts/verify.ps1`, 모바일 회귀는 실제 로컬 DB/Edge와 frontend build 후 e2e에서 `npm run test:e2e`로 수행한다. 연속 서버 검사는 로컬 Supabase/Cron 실행과 `node scripts/prepare-member-e2e.mjs`의 가상 동의/계정 준비 후, 루트에서 `node scripts/verify-prd-integration-local.mjs`로 실행한다. 전체 기반·모바일·연속 검사는 공유 fixture 경합을 피하도록 순차 실행한다. 검사는 가상 로컬 fixture를 만들고 정리하며 운영 DB를 대상으로 실행하지 않는다.

검증 CI는 배포 실행 소스 `d2c40c0` 기준이다. 이후 추가한 이 보고서·연속 검사 스크립트·API 배포 상태 문서는 프론트/함수/DB 실행 소스를 변경하지 않는다.
